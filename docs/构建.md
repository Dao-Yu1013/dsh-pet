# 构建

工程没有 Gradle，所有步骤都在 `build.ps1` 里。脚本不长，但依赖一堆外部工具，第一次跑起来会有点麻烦。

## 需要准备什么

- **JDK 17**：`javac` 和 `jar` 要用，R8 也跑在它上面。
- **Android SDK**：build-tools 36.0.0、platform android-36、cmdline-tools（里面带 `r8.jar`）。
- **NDK 28.2.13676358**：只编译一个 `dshcore.cpp`，但版本号要对。
- **Live2D Cubism Core**：闭源，得自己去 [Live2D 官网](https://www.live2d.com/sdk/download/cubism-sdk/) 下 Cubism SDK for Java。
  - `CubismCore.jar` 放到 `app/libs/Live2DCubismCore.jar`
  - `libLive2DCubismCoreJNI.so` 放到 `app/src/main/jniLibs/arm64-v8a/`
  - 仓库里这两个文件都没有，缺了 `build.ps1` 会直接报错告诉你路径。
- **签名文件**：自己的 keystore。仓库里不放任何签名密钥。

`app/libs` 里已经带了三个构建用的 jar：ECJ（手机端 Java 编译器）、R8 8.0.34（手机端 D8 运行时）、Android API 16 编译桩。三个都是开源许可，notice 在同目录。

## 跑起来

```powershell
$env:ANDROID_SDK_ROOT = "D:\android-sdk"
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"

powershell -ExecutionPolicy Bypass -File .\build.ps1 `
  -JdkPath $env:JAVA_HOME `
  -KeystorePath "D:\keys\dsh.keystore" `
  -KeystorePass "你的密码" `
  -Version "2.6.2" -VersionCode 106
```

默认输出到 `dist\dsh-pet-v2.6.2.apk`。想换名字加 `-OutputPath`，脚本不会覆盖已经存在的文件。

工具链路径的优先级是：命令行参数 → 环境变量（`ANDROID_SDK_ROOT` / `ANDROID_HOME` / `JAVA_HOME`）→ 仓库里的 `.toolchain\android-sdk` 和 `.toolchain\jdk-17`。

## 脚本做了哪些事

1. `aapt2 compile` 编译资源，`aapt2 link` 生成临时 manifest、`R.java` 和基础 APK。
2. `javac --release 11` 编译全部 Java 源码。
3. 正式包走 R8：混淆、收缩、优化，mapping 存到 `build/mapping/`。加 `-Fast` 则跳过 R8 和前端加密，直接用 D8。
4. 正式包把九个前端文件加密成 `sec.bin`，快速包原样打包。
5. clang 分别编 `arm64-v8a` 和 `armeabi-v7a` 的 `libdshcore.so`。
6. 把 ECJ、R8 和 Android API 桩转成手机端能加载的 DEX 资源。
7. 重新封装 assets、`classes.dex`、原生库。
8. `zipalign` 对齐，`apksigner` 出 v1/v2/v3 签名。

R8 的 mapping 一定要留着。线上崩溃栈要靠它还原，换了版本就不能混用。

## 几个坑

**aapt2 不认中文路径。** 项目路径里有中文，`aapt2` 会在链接阶段报奇怪的错。解决办法是映射一个纯英文盘符再进目录：

```powershell
subst Z: "E:\dsh-pet"
cd Z:\dsh-pet
```

**clang 不要手写 `-I`。** 脚本里用 `--target=aarch64-linux-android28` 让 clang 自己推 sysroot，手写头文件路径的话 armeabi-v7a 会串到 arm64 的头。

**`libc++_shared.so`。** `dshcore.cpp` 里用了 C++ 运行时，必须加 `-static-libstdc++`，否则 so 会依赖一个包里没有的库，装上去就报"核心组件缺失"。脚本里还有一层兜底，检测到依赖就把 NDK 里那个 so 一起打进去。

**Live2D 只有 arm64。** 官方 JNI 库只给了 arm64-v8a，armeabi-v7a 上没有，运行时会自动降级。别自己编一份 v7a 的，没有对应 Core。

**签名和 `kCert`。** 应用启动时会用 `dshcore.cpp` 里写死的证书指纹校验自己。你用自己的 keystore 签名，就必须把 `kCert` 改成你的证书 SHA-256，同时把 `-ExpectedCert` 传给脚本做自检，否则装上去会被拦成"签名校验不通过"。三处（keystore、脚本参数、`kCert`）必须一致。

**升级装不上。** 覆盖安装要求签名一致、versionCode 比已装的大。签名换了就只能卸载重装，数据会丢，先导出备份。

## 检查产物

```powershell
aapt dump badging dist\dsh-pet-v2.6.2.apk
apksigner verify --print-certs dist\dsh-pet-v2.6.2.apk
zipalign -c 4 dist\dsh-pet-v2.6.2.apk
```

`badging` 看包名、版本号、minSdk；`verify` 看签名和证书指纹；`zipalign -c` 返回空就是对齐没问题。

构建成功不等于功能正常。聊天、悬浮窗、无障碍这些还是要装到手机上跑一遍。
