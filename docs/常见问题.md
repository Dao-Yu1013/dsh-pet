# 常见问题

**打开就白屏，或者一直停在启动动画**

正式包的前端是加密的，启动时由 `WebUI` 解到私有目录再加载。白屏一般是解密失败了，最可能的原因是装了一个签名不一样的包。卸载重装同签名的版本，数据会清空，先想清楚。

**点了"放出来"没反应**

检查悬浮窗权限有没有给。给了还是不出来，看看应用有没有被系统冻结，电池优化和厂商自启动管理都要放行。

**发消息没有回复**

先看气泡里的提示。没填 Key、地址写错、模型名不对、余额不足、限流，这几种都会直接把原因写出来。请求最长等 210 秒，超时会提示。本地模型没配的时候，走远端 AstrBot 也可能失败，两个都要查。

**图片发出去了，她说没看到**

看图需要单独的视觉模型，光配聊天模型不够。另外如果视觉请求组装失败，应用会明说"识图没成功"，不会假装看到了。

**按住说话没反应**

检查麦克风权限，还有系统里有没有启用语音识别服务。有些机型需要先在系统设置里装语音服务。识别最多等 10 秒，返回中间结果也会用。

**桌宠过一会儿就消失**

前台服务被系统杀了。把电池优化关掉，允许自启动，最近任务里也别随手划掉。不同厂商的杀后台策略差别很大，只能一项项试。

**QQ 一直连不上**

按顺序查：

1. 地址是不是填了 `127.0.0.1`。除非 NapCat 和桌宠在同一台手机上，否则要填 NapCat 那台设备的内网 IP。
2. token 两边是不是一致。401 一般是 token 错。
3. 端口和路径对不对，NapCat 默认正向 WS 是 `3001`，路径 `/`。
4. 两台设备在不在同一个 Wi-Fi。访客网络、AP 隔离、VPN 都会挡住。
5. 防火墙有没有拦。电脑上第一次连会弹提示。

404 通常是路径不对，连接超时基本是网络不通。

**同一条 QQ 消息回了两次**

说明还有另一个程序也在用这个 QQ 号回复，一般是 AstrBot 的原生 QQ 适配器。打开设置里的"让位"开关，让桌宠不抢答；或者把另一边的 QQ 连接关掉。

**群聊里 @ 她也不回**

群聊默认只在被 @ 时回应。先确认群配置里这个群被放行了，再看是不是开了"自由参与"反而把 @ 识别搞乱了。群聊用的是单独的人设，人设卡没配好也会安静。

**插件装上了但没动作**

先看插件页有没有报错，再看 `last_error.json`。原生插件要检查 manifest 里的入口、启用状态和触发配置。AI 生成的插件失败时应该给出真实编译错误，没有的话就是没跑起来。

**升级装不上，提示签名冲突**

新的安装包和手机里那个不是同一个签名。要么找回原来的 keystore 重新签，要么卸载重装，重装前先在旧版本里导出数据。

**数据存在哪，怎么备份**

应用私有目录 `files/S-G`。设置里的"S-G 数据"可以整包导出，得到一个压缩文件，换手机时导入就行。导入会覆盖本地数据，先导一份当前的再操作。

**广告跳过点了没反应**

这条链路要求无障碍服务开着、规则命中了、按钮真的可点。开发者模式里有规则测试，测试模式只记录命中不点击，能先确认规则对不对。别指望它点"关闭"之外的按钮，点赞、购买这类动作是被明确排除的。

**识海很卡**

节点多了就卡，尤其老机器。把自动旋转关掉，或者少开一点记忆。WebGL 不可用时会自动降级到 Canvas，效果差一些但不会白屏。
